# 작가님이 코딩 없이 직접 고치는 방법 (검토안)

작성: 2026-10-21, 홈페이지 제작 터미널. 미니 회사 회의 307d6a "은영작가님이 쉽게 홈페이지 수정 가능하게" 요청에 대한 정리.
> **결정(2026-10-21, 고운대표):** 작가님 수정은 **응접실(`/studio`)을 통해서** 받는다. 작가님이 응접실에서 '은솔'에게 사진·글·일정을 요청 → 요청이 구글 시트(앱스 스크립트)로 모임 → 이 제작 터미널이 은솔로서 고치고 화면을 보여 줌 → 고운대표 "올려"로 반영. 아래 비교는 그 결정 전 검토 기록으로 남겨 둔다. 응접실은 지금 시험 모드(시트 연결 전).

## 1. 지금 홈페이지 구조

- **호스팅:** GitHub Pages(무료). 저장소 `choieunyoung-writer/choieunyoung-writer.github.io`의 `main`에 들어간 파일이 1~2분 뒤 그대로 사이트가 됨. 빌드 과정 없음(그냥 HTML).
- **파일**
  - 페이지: `index.html`(홈), `works.html`(작품), `book-*.html`(책 상세 4권 + 공통 `book.html`), `news.html`(소식), `about.html`(소개), `contact.html`(연락)
  - 디자인: `style.css` 하나, 책 펼침 모션 `book-open.js`
  - 이미지: `images/`(표지 6장, 작가 사진)
  - 영어판: `en/` — 한국어 페이지에서 `tools/make_en.py`로 자동 생성
- **글은 HTML 안에 직접 들어 있음.** 문장 하나를 바꾸려 해도 HTML 파일을 열어 태그 사이 글자를 고쳐야 함 → 작가님이 직접 고치기 어려운 구조.
- **이미 준비된 것:** 소식 페이지 일정 칸은 구글 캘린더를 끼우게 만들어 둠(캘린더 ID만 넣으면 작가님이 캘린더에 쓴 일정이 자동으로 보임).

## 3. 방법 비교

### 방법 A. 요청만 하기 (지금 방식) — 추천: 당장
작가님이 카톡 또는 GitHub '수정 요청(Issue)'으로 "어디를 어떻게"만 알려 주면, 제작 터미널이 고치고 화면을 보여 준 뒤 고운대표 "올려"로 반영.
- 장점: 작가님은 배울 것 없음. 실수로 화면이 깨질 일 없음. 확인 후 공개.
- 단점: 작가님 혼자서는 못 바꿈. 반영까지 사람(고운대표)을 거침.
- 준비: 끝남(노션 안내 2쪽 작성 완료). 선택: Issue 양식 추가.

### 방법 B. 구글 캘린더·구글 시트로 "자주 바뀌는 칸"만 직접 — 추천: 다음 단계
- **일정 → 구글 캘린더:** 공개 캘린더 하나 만들어 ID를 넣으면 끝. 작가님은 휴대폰 캘린더에 쓰기만 하면 소식 페이지에 자동 반영.
- **짧은 소식·문장 → 구글 시트:** 시트를 '웹에 게시'해 두고, 사이트가 열릴 때 시트 내용을 읽어 보여 주는 칸을 만듦(예: 소식 목록, 홈 '문장 한 줄').
- 장점: 작가님에게 익숙한 도구. 바로 반영. 디자인은 사이트가 그대로 지킴(작가님은 글만 씀).
- 단점: 작가님이 쓴 내용이 **확인 없이 바로 공개**됨. 시트·캘린더는 공개 상태여야 함. 시트로 바꿀 수 있는 칸만 바뀜(소개 전체·책 페이지는 어려움). 구글 쪽이 느리거나 막히면 그 칸이 비어 보일 수 있음(대비책: 비면 기존 글 표시).
- 준비: 캘린더는 ID만 받으면 30분. 시트 연결은 반나절.

### 방법 C. 웹 편집 화면(정적 사이트용 CMS) 붙이기 — 검토: 작가님이 직접 많이 고치고 싶어 하실 때
GitHub 저장소 위에 '글쓰기 화면'을 얹는 도구. 예: Pages CMS, Decap CMS. [도구별 무료 조건·로그인 방식은 확인 필요 — 자료조사 터미널에 맡길 것]
- 작가님은 블로그 글쓰기 같은 화면에서 칸(제목·소개·문장·사진)을 채우고 저장. 저장하면 저장소에 기록되고 사이트에 반영.
- 장점: 소개·책 소개·사진까지 작가님이 직접. 모든 수정 기록이 남아 되돌리기 쉬움.
- 단점: 지금 HTML에 박힌 글을 '데이터 파일(칸)'로 옮기는 큰 공사가 필요(사이트 구조 변경). 작가님 GitHub 계정과 로그인 필요. 설정에 따라 저장 즉시 공개될 수 있어, '임시 저장 → 고운대표 확인 → 공개' 흐름을 따로 맞춰야 함.
- 준비: 2~3일 공사 + 시험.

### (참고) 방법 D. 노션·아임웹 같은 서비스로 옮기기 — 비추천
작가님은 편하지만 지금 디자인(표지 색, 책 펼침 모션, 매거진 소개)을 거의 다시 만들어야 하고, 월 비용이 생길 수 있음.

## 4. 제안 순서

1. **지금:** 방법 A 유지 + 구글 캘린더 연결(작가님이 캘린더 쓰는 데 동의하시면 ID만 주세요).
2. **작가님이 직접 하고 싶어 하시면:** 방법 B로 소식·문장 한 줄부터.
3. **그래도 더 많이 직접 고치고 싶으시면:** 방법 C 공사. 그 전에 자료조사로 도구 비교.
