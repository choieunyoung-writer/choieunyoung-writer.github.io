# 커스텀 도메인 연결: www.choieunyoung.net — ✅ 완료 (2026-11-17)

도메인은 작가님이 가비아에서 이미 등록하셨어요. 주소 안내(DNS)는 **클라우드플레어**에서 하기로 정했어요(고운대표 결정, 플랜짐 예약앱 터미널 자문 참고 — 작가님 사이트는 정적 소개 사이트라 서버 기능은 필요 없지만, 관리 방식을 다른 프로젝트와 맞추기 위해 클라우드플레어 선택). 사이트 파일은 그대로 **GitHub Pages**에서 서비스해요(깃허브 저장소는 바뀌지 않음).

## 1. 저장소 설정 (완료, main에 반영됨)
- 저장소 루트의 `CNAME` 파일 내용: `www.choieunyoung.net`
- 이 값은 DNS를 어디서 관리하든(가비아든 클라우드플레어든) 똑같아요.

## 2. 클라우드플레어에 도메인 추가 (대표님)
1. https://dash.cloudflare.com 로그인 → **Add a site** → `choieunyoung.net` 입력 → Free 플랜 선택
2. 클라우드플레어가 기존 DNS 기록을 가져오려 시도함 (가비아에 등록된 기록 없으면 빈 상태로 진행)
3. 클라우드플레어가 보여 주는 **네임서버 2개**(예: xxx.ns.cloudflare.com)를 복사해 둠

## 3. 가비아에서 네임서버 변경 (대표님)
1. 가비아 **My가비아 → 도메인 관리 → choieunyoung.net → 네임서버 설정**
2. 기존 `ns.gabia.co.kr`을 클라우드플레어가 준 네임서버 2개로 교체 → 저장
3. 반영까지 몇 분~최대 24시간 걸릴 수 있음 (클라우드플레어 대시보드에서 "Active" 상태로 바뀌면 완료)

## 4. 클라우드플레어 DNS에 www 레코드 추가 (대표님)
클라우드플레어 **DNS → Records → Add record**
| Type | Name | Target | Proxy status |
|---|---|---|---|
| CNAME | www | choieunyoung-writer.github.io | **DNS only (회색 구름, 꺼짐)** |

- 처음엔 반드시 프록시를 꺼 둬야 GitHub가 도메인 소유를 확인하고 인증서를 발급할 수 있어요. 켜 두면 연결이 실패해요.
- 루트 주소(`choieunyoung.net`, www 없는 주소)도 쓰려면 클라우드플레어의 "Redirect Rules" 또는 CNAME flattening으로 www로 넘기는 설정을 추가해요(필요해지면 별도 안내).

## 5. GitHub 설정 (대표님 계정에서)
- 저장소 Settings → Pages → Custom domain에 `www.choieunyoung.net` 입력 → Save
- DNS 확인(초록 체크)이 끝나면 "Enforce HTTPS"를 켜요. 인증서 발급에는 시간이 걸릴 수 있어요.

## 6. (선택) 클라우드플레어 프록시 켜기
- 5번까지 끝나고 사이트가 새 주소로 정상적으로 열리는 걸 확인한 뒤에만, 클라우드플레어 DNS에서 www 레코드의 프록시(주황 구름)를 켤지 정해요. 켜면 클라우드플레어의 캐시·보안 기능이 적용돼요. 끄고 그대로 둬도 문제없어요.

## 7. 확인 후 할 일
- 새 주소로 홈·소개·작품·연락 페이지가 열리는지 확인 (휴대폰·PC)
- 사이트 안의 기존 `choieunyoung-writer.github.io` 주소 표시(검색용 주소·언어 연결)를 새 주소로 바꿀지는 확인 후 결정
- 시안 표시(noindex)는 작가님 최종 확인 후에만 지움

## 주의
- 클라우드플레어 계정은 대표님(또는 작가님) 명의로 만들고, 로그인 정보는 이 저장소나 대화에 적지 않아요.
- 네임서버를 바꾸는 동안 메일(이메일) 설정이 가비아에 따로 있다면(MX 레코드 등), 클라우드플레어로 옮긴 뒤 그 기록도 그대로 옮겨야 메일이 끊기지 않아요. 지금은 메일 관련 기록이 없는 것으로 확인됨(2번 2단계에서 빈 상태로 시작).
